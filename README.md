# dsh-ru-search

MCP-сервер для [DeepSeek Harness (dsh)](https://www.npmjs.com/package/@deepseek-ai/dsh) и любого другого MCP-клиента (stdio):

- **`yandex_search`** — поиск Яндекса **без API** (разбор HTML выдачи);
- **`web_open`** — открыть любой сайт и получить текст страницы; запросы оформлены как у Яндекс.Браузера, а корневые сертификаты **Минцифры** (Russian Trusted Root/Sub CA) считаются доверенными, поэтому открываются сайты, на которых обычный `fetch` падает с ошибкой сертификата (например `atsenergo.ru`, `sberbank.ru`);
- **`yandex_fetch`** — алиас `web_open`.

Без зависимостей, один файл, Node.js ≥ 18, лицензия MIT.

## Установка

```bash
npm install -g github:VyachL84/dsh-ru-search
# команда: dsh-ru-search
```

или без установки: `npx -y github:VyachL84/dsh-ru-search`.

### Подключение к dsh

Файл патча (`--patch my.patch.yml`, формат слоёв cordis; для `dsh --profile web --patch ...`):

```yaml
- insert:
    - id: mcp-yandex
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: yandex
        transport: stdio
        command: dsh-ru-search      # или абсолютный путь: $(npm root -g)/../bin/dsh-ru-search
```

Инструменты появятся у агента как `mcp__yandex__yandex_search`, `mcp__yandex__web_open`.
Для других MCP-клиентов — запускайте `dsh-ru-search` как stdio-сервер.

При первом вызове плагин сам скачивает корни Минцифры с `gu-st.ru` в `~/.dsh-ru-search/certs`
(каталог — `YA_CERT_DIR`, отключить загрузку — `YA_NO_CERT_DOWNLOAD=1`, тогда положите `russian_trusted_root_ca.crt` / `russian_trusted_sub_ca.crt` туда сами).
Отпечатки SHA-256 для самостоятельной проверки:

| Сертификат | SHA-256 | Действует до |
|---|---|---|
| Russian Trusted Root CA | `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31` | 27.02.2032 |
| Russian Trusted Sub CA | `BB:BD:E2:10:3E:79:0B:99:9E:C6:2B:D0:3C:F6:25:A5:A2:E7:C3:16:E1:0A:FE:6A:49:0E:ED:EA:D8:B3:FD:9B` | 06.03.2027 |

> Корни добавляются **только в доверенные для этого процесса** (поверх системных корней Node), в систему ничего не устанавливается.
> Если вы не доверяете УЦ Минцифры — не используйте плагин для сайтов, где важна конфиденциальность: владелец такого УЦ технически может выпустить сертификат на любой домен.

## Инструменты

| Инструмент | Параметры |
|---|---|
| `yandex_search` | `query` (обяз.), `page` (с 1), `count` (1–30, по умолч. 10), `site` (ограничить доменом), `region` (код `lr`: 213 — Москва, 2 — Санкт-Петербург) |
| `web_open` | `url` (обяз.), `max_chars` (500–100000, по умолч. 20000), `links` (добавить список ссылок страницы), `referer` (по умолч. `https://yandex.ru/`), `insecure` |

### Как выглядят запросы

User-Agent и `sec-ch-ua` Яндекс.Браузера, русские `Accept-Language`, `Sec-Fetch-*`, Referer `https://yandex.ru/` («переход из Яндекса»),
cookie сохраняются между вызовами, редиректы (до 6) сохраняют заголовки, хост с точкой на конце (`example.ru.`) нормализуется.

### Сертификаты

- **Корни Минцифры** — см. выше.
- **Недостающие промежуточные сертификаты (AIA).** Если сайт не присылает промежуточный сертификат (как, например, `np-sr.ru`), плагин один раз докачивает его по ссылке *CA Issuers* из сертификата и повторяет запрос — как браузер. Докачанный сертификат принимается **только** если цепочка проверена до доверенного корня; иначе запрос отклоняется.
- **`insecure: true`** — отключает проверку сертификата для одного вызова (ответ помечается предупреждением). Нужно для сайтов с по-настоящему сломанным сертификатом (просрочен, заглушка хостинга вроде `*.domainparking.ru`). Корни Минцифры такие случаи не лечат. Используйте осознанно: возможна подмена сервера.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `YA_CERT_DIR` | `~/.dsh-ru-search/certs` | каталог с `*.crt`/`*.cer` дополнительных корней |
| `YA_NO_CERT_DOWNLOAD` | — | `1` — не скачивать корни Минцифры автоматически |
| `YA_REGION` | `213` | регион поиска по умолчанию (`lr`) |
| `YA_BROWSER_VERSION` / `YA_CHROMIUM_VERSION` | `25.8.0.0` / `138` | версии в User-Agent и client hints |
| `YA_USER_AGENT` | собирается из версий | полностью свой User-Agent |
| `YA_ALLOW_PRIVATE` | — | `1` — отключить защиту от SSRF (разрешить внутренние адреса) |
| `YA_ALLOW_HOSTS` | — | список имён хостов через запятую, исключённых из защиты |

**Защита от SSRF (с 1.0.1).** Плагин отказывается открывать loopback, частные сети, link-local (в том числе метаданные облака `169.254.169.254`), CGNAT, `localhost`, `*.local`, `*.internal`, `*.svc`, `*.cluster.local`. Проверяются IP в URL, результат DNS в момент соединения (защита от DNS rebinding), каждый редирект и докачка сертификатов. Это важно, если плагин запускается агентом внутри сети: ссылку на внутренний адрес может подсунуть загруженная страница.

## Ограничения (читайте до использования)

- **Капча.** Яндекс может показать SmartCaptcha, особенно с IP дата-центров. Плагин **не решает и не обходит** капчу: он возвращает понятную ошибку, агенту стоит перейти на другой поиск. Выдача с одного и того же IP то проходит, то блокируется.
- **Разбор выдачи** основан на текущей разметке Яндекса (`parseSerp`); при её изменении поиск перестанет находить результаты — нужна правка. Тесты используют синтетический HTML.
- **Маскировка — только на уровне HTTP-заголовков.** TLS-отпечаток остаётся отпечатком Node.js, поэтому защиты, анализирующие его, плагин не обманет.
- **JavaScript не выполняется** (как у `curl`): страницы, собираемые на клиенте, дадут мало текста.
- **Правила использования.** Автоматические запросы к сервисам Яндекса могут противоречить их условиям использования; ответственность за соблюдение правил и законодательства лежит на пользователе. Для промышленных объёмов используйте официальный Yandex Search API.
- Текст чужих сайтов, попавший в контекст модели, может содержать инструкции (prompt injection) — не выполняйте их без проверки.
